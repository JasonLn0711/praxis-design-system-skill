# Praxis acceptance evidence

Use the checks that can demonstrate the requested outcome. Run the project's required commands and exercise the normal user entry point when a functioning UI is part of the deliverable.

| Dimension | Evidence to inspect |
| --- | --- |
| Task and behavior | The primary action through a real route or component with keyboard and pointer or touch where applicable. Cover affected loading, empty, validation, error, recovery and success states. Use real data where in scope and identify mock or fixture evidence. |
| Fidelity and craft | Compare the rendered result with the selected direction, existing system, or supplied design. Inspect hierarchy, composition, copy, actual assets, semantic tokens, typography, density and state consistency. Capture locations and the underlying evidence for any finding. |
| Responsive and accessible behavior | Test representative wide and narrow widths, breakpoint transitions or long content as relevant, zoom/reflow, contrast, focus order, hit targets and readable accessible names. Confirm bilingual/RTL behavior where supported. |
| Motion and performance | Compare standard and reduced-motion paths. Check for layout shifts, obscured content, touch fallbacks, unexpected network work and missing 3D fallback. Measure or replay performance if the change affects the experience. |
| Diagram or export | Open the actual artifact at intended sizes. Confirm its relation and encoding, visual hierarchy and labels, reading order, accessibility, and export variant or format. |

Report each applicable dimension independently. Use severity and reproduction details for audit findings. For implementation, repair issues within scope and rerun the affected checks. Distinguish a static check, a rendered screenshot, an exercised flow, and an observed public release when reporting verification. If browser or live-account evidence is unavailable, say which specific observations are still open.

For a style selection, include the brief constraint that decided the outcome, the source record ID and the first observable check. For example, a low rendering-cost filter can rule out a gallery's 3D direction using catalog metadata. Confirm the chosen treatment with actual image sizes, the intended device and the gallery-to-detail navigation path when delivering a working gallery. For a design-only brief, hand over those checks as acceptance criteria.
